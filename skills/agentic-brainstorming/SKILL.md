# Agentic brainstorming

Use this skill only when a material choice is unresolved, such as ambiguous outcomes or approaches with meaningfully different consequences. Do not turn routine implementation details into approval gates.

Safety rules, permissions, harness instructions, the user request, and applicable repository instructions remain authoritative. Repository instructions may specialize this default.

## Procedure

1. Clarify the outcome, constraints, affected boundary, and evidence needed for a decision.
2. Separate settled facts from assumptions and open questions.
3. Present a proportionate set of viable options, including trade-offs, risks, reversibility, and compatibility effects.
4. Recommend one option and explain why it best fits the evidence.
5. Confirm the direction before work that depends on the material choice.

Keep decisions in the active interaction by default. Persist a decision only when the user asks or applicable repository instructions already require it and the task authorizes that write. Do not invent a decision log, memory store, hidden state, or other process.

Once the direction is settled, preserve its boundary. Return here only when new evidence creates another material choice.
