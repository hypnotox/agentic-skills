## Findings and changes

### 1. Review reporting excludes useful improvement opportunities

**Instruction defect; medium impact.** The [reviewing skill](https://github.com/hypnotox/agentic-skills/blob/93740076e5cd988f438b9976b6d9fb4465466025/skills/agentic-reviewing/SKILL.md#L16) and [reviewer role](https://github.com/hypnotox/agentic-skills/blob/93740076e5cd988f438b9976b6d9fb4465466025/agents/reviewer.md#L24) allow only defects or risks. Review principles 1–4 recognize improvement opportunities while requiring evidence, purpose, and material benefit.

An improvement audit following those instructions must omit a useful opportunity or overstate it as a risk. The exclusion is directly observable in the text; its effect on previous agent runs has not been established.

Allow relevant, evidence-backed opportunities in both the skill and role. Distinguish finding types, explain concrete consequences or benefits, qualify consequential uncertainty, and consolidate related observations. Keep preferences from becoming findings and optional improvements from becoming mandatory corrections. Both files must change because role boundaries constrain loaded skills.

### 2. Security wording can discount concrete evidence without a threat profile

**Grounded interpretation risk; medium impact.** [Code design](https://github.com/hypnotox/agentic-skills/blob/93740076e5cd988f438b9976b6d9fb4465466025/skills/agentic-code-design/SKILL.md#L26) and [brainstorming](https://github.com/hypnotox/agentic-skills/blob/93740076e5cd988f438b9976b6d9fb4465466025/skills/agentic-brainstorming/SKILL.md#L20) restrict security choices to an explicit profile and established trust assumptions. Coding principle 6 permits an explicit requirement or a concrete project-specific risk; working principle 3 also recognizes grounded risks and material unknowns.

The narrower wording can be read as disqualifying project evidence until a profile is declared. Brainstorming already permits surfacing missing scope, so this is an ambiguity, not proof that risks were ignored.

Use explicit requirements, established trust assumptions, and concrete project evidence as the basis for security decisions. Clarify that recognizing an evidenced risk does not require a documented profile. Preserve the existing decision authority and prohibition on invented threats, speculative defenses, or silent scope expansion.

### 3. Guidance artifacts need explicit applicability and obligation

**Improvement opportunity; low impact.** [Artifact design](https://github.com/hypnotox/agentic-skills/blob/93740076e5cd988f438b9976b6d9fb4465466025/skills/agentic-artifact-design/SKILL.md#L8) includes skills and instructions, but its [drafting guidance](https://github.com/hypnotox/agentic-skills/blob/93740076e5cd988f438b9976b6d9fb4465466025/skills/agentic-artifact-design/SKILL.md#L41) prefers authoritative prose without a conditional check for requirements, defaults, and options. Instruction principles 1–5 make these distinctions consequential; artifact principle 3 requires clear content status.

Add one short paragraph for guidance artifacts and make tense and voice follow content status. This helps keep recommendations from becoming obligations and examples from adding requirements. It is missing coverage, not evidence of a demonstrated output failure. A separate instruction-writing skill or phase would add unnecessary routing.

### 4. A package test rejects unrelated local Claude settings

**Test-contract defect; medium impact.** The [obsolete-machinery check](https://github.com/hypnotox/agentic-skills/blob/93740076e5cd988f438b9976b6d9fb4465466025/tests/package-shape.test.ts#L136-L154) rejects any local `.claude` directory. The [package allowlist](https://github.com/hypnotox/agentic-skills/blob/93740076e5cd988f438b9976b6d9fb4465466025/package.json#L12-L19) already excludes it. Coding principle 7 calls for meaningful contract tests rather than incidental structure.

Reproduction: all five tests pass in the original checkout; adding only `.claude/settings.local.json` containing `{}` causes the obsolete-machinery test to fail. No distributed file changed. Remove only that directory from the absence assertion. Retain the checks for obsolete AWF machinery and package mappings.

## Why retain the current design

- Planning already sequences coherent changes and actual dependencies, preserves settled decisions, and leaves routine mechanics revisable.
- Code design provides useful ownership, reuse, failure-contract, and bounded-refactor guidance. Implementation and debugging tie verification to agreed behavior and relevant failures.
- Context and premise checking distinguish observations, inferences, unknowns, and affirmative evidence. Artifact design respects local contracts and authoritative sources without adding a separate workflow.
- Fresh delegated roles retain explicit input and authority boundaries. The literal `none` requirement was considered but retained: it explicitly accounts for constraints in a fresh context; relaxing it needs evidence that equivalent briefs preserve that assurance.
- Caller and role descriptions overlap, but no conflicting brief definition was established. Consolidation would require balancing maintenance cost against independently usable roles and caller guidance. It is not a prerequisite for these corrections.

Do not add a doctrine-loading dependency, generated instructions, another skill, or orchestration. The existing structure serves the product; the findings do not establish a need to replace it.
